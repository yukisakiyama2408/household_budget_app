# 本番入口の通信確認（2026年11月7日）

対象： https://money-memo-app.vercel.app/

認証情報を付けない読み取り専用のHTTP GETで確認。アプリの変更・デプロイ・DBへのアクセスや更新は行っていない。測定値はこの実行環境からの値で、ユーザーの端末の通信やブラウザ描画は含まない。

## 観測

- `/` は307で `/login` へ転送する。
- 最初の単独GET：最初の応答まで0.216509秒、全体0.216893秒。
- 転送込みのGET：`/login` が200、転送1回、最初の応答まで0.466389秒、全体0.467072秒。
- 別のcurl実行で `/` と `/login` を3組、順にGETした結果：

| 回 | `/` 最初の応答／全体 | `/login` 最初の応答／全体 |
| --- | --- | --- |
| 1 | 0.242785秒／0.243059秒 | 0.481158秒／0.490005秒 |
| 2 | 0.113852秒／0.113980秒 | 0.329574秒／0.333570秒 |
| 3 | 0.097003秒／0.097123秒 | 0.276331秒／0.277188秒 |

同一curlプロセス内では接続が再利用される場合がある。繰り返しの短縮だけでコールドスタートやキャッシュの効果とは判断しない。

ログイン画面の応答には以下のヘッダーを確認：

- `x-vercel-id: hnd1::iad1::...`
- `x-matched-path: /login`
- `x-vercel-cache: MISS`
- `cache-control: private, no-cache, no-store, max-age=0, must-revalidate`

Vercelの説明ではx-vercel-idは経由地域・Functionの実行地域を示す。hnd1は東京、iad1は米国ワシントンD.C.。

参照：
- https://vercel.com/docs/headers/request-headers#x-vercel-id
- https://vercel.com/docs/regions
- https://vercel.com/docs/functions/configuring-functions/region

## 判断できることと次の確認

未ログインの入口・ログインHTMLの応答で数秒単位の継続的な待ちは、この少数の測定では観測しなかった。ログイン後のホーム表示の遅さを否定する結果ではない。JS・画像・フォント・RSC・描画・操作可能になるまでの時間も未計測。

少なくとも観測したログイン画面の処理は米国側で行われている。全画面が同じリージョンか、実際のSupabaseの配置や本番設定がどうなっているかは未確認。DBが東京など別地域なら、Functionとの往復が待ち時間の原因候補になる。VercelはDBと同地域または近い地域での実行を推奨している。

次にSupabaseのリージョンを確認し、VercelのFunction配置と比較する。配置が一致していれば、認証後のサーバーログ・取得時間とブラウザのNetworkを計測して原因を絞る。確認前に配置や料金プランを変更しない。
